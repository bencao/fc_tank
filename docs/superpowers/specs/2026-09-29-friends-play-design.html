FC Tank: Friends Play

Design · 2026-09-29 · branch feat/friends-play

Summary

Online two-player co-op. One player picks FRIENDS PLAY on the title screen, and the game makes a room and shows an invitation link (/?join=K7QX2M) with a COPY / SHARE button. The friend opens the link and joins. They then play the classic 2P game together, each in their own browser, as P1 and P2. After a game over, each friend enters their own initials on their own screen, and the run goes on the global leaderboard as one team entry: ABC&XYZ with the combined score.

Decisions

QuestionDecisionWhy
Transport WebRTC data channel, peer to peer. Signaling through /api/room on the existing Upstash Redis. Lowest latency, no new vendor, nothing billed per message. The game is already on Vercel functions + Upstash.
Who simulates The host is authoritative: only the host runs the battle. The guest is a remote keyboard plus a screen mirror. The engine uses Math.random and variable rAF deltas. Lockstep would need a deterministic rewrite; mirroring works with the engine as it is.
What is mirrored Scene switches, whitelisted View method calls, battle frames (sprites + terrain diffs + explosions), and sounds. Views are already a narrow API. The guest drives its own copies of the same views, so it looks identical.
ICE Non-trickle (gather all candidates, then post the SDP once). Public STUN, no TURN. One offer and one answer means two Redis writes. Without TURN, roughly 10–20% of NAT pairs can't connect; the UI says so plainly. Adding TURN later only changes ICE_SERVERS.
Team score One leaderboard row. Name ABC&XYZ (host first), score = P1 + P2. "X & Y" as asked. The server accepts one or two sets of initials.
Local 2P Unchanged (separate rows per player). Out of scope. It could adopt team entry later.

Messages

TypeDirectionPayload
keyguest → host{key: "ArrowUp", down: true}. Only keys the game understands; repeats dropped.
initialsguest → host{name: "XYZ"}
scenehost → guest{name: "battle_field"}
viewhost → guest{view, method, args}, only for whitelisted methods; map units are sent as {area}
framehost → guest{units: [[id, kind, anim, x, y, rot]], terrain: {add, remove}, booms: [[x, y]]}
soundhost → guest{name}
name_entryhost → guest{score}: team score; guest starts its own initials entry

All messages share one reliable, ordered channel. Frames carry every tank, missile and gift in full. Terrain only goes out as a diff against what was last sent (the first frame of a battle carries all of it), so terrain needs the reliable channel. Frames go out at most every 33 ms, which is about 1–2 KB per frame.

Scene flow

stateDiagram-v2
  [*] --> welcome
  welcome --> lobby: FRIENDS PLAY + ENTER (host)
  [*] --> lobby: opened /?join=CODE (guest)
  lobby --> welcome: SPACE (cancel) / error + ENTER
  lobby --> stage: friend joined + host ENTER
  stage --> battle_field
  battle_field --> report
  report --> stage: stage cleared
  report --> name_entry: game over, team scored
  report --> lobby: game over, no score
  name_entry --> high_scores: both initials in → one team row
  high_scores --> lobby: still connected → play again
  high_scores --> welcome: friend gone

The guest never moves between scenes on its own. It follows the host's scene messages. The exceptions are its own lobby (joining, errors) and its initials entry.

Controls

  • Both friends use the 1P keys, each at their own keyboard: arrows move and Z fires (or the touch pad). The host's drive P1; the guest's drive P2. ENTER on either side pauses the shared game.
  • While friends play is on, the page shows only the 1P card, retitled "YOUR CONTROLS". WASD + J still work quietly as a fallback, so nobody used to the 2P keys gets stuck.
  • If the guest's window loses focus, every key it holds is released, so its tank can't keep driving.

Failure handling

CaseBehaviour
Room missing / expiredGuest: "ROOM NOT FOUND". ENTER goes to the title screen and drops ?join from the URL.
Room already has a guest"ROOM IS FULL" (409).
ICE fails / 20 s timeout"COULDN'T CONNECT". Probably a strict NAT; both sides can try again.
Guest leaves mid-gameHost plays on alone: P2's keys are released and its tank idles. Afterwards the host goes to the title screen, not the lobby.
Host leavesGuest: "HOST LEFT", then ENTER for the title screen.
AbuseRoom creation limited per IP per hour; SDP must look like SDP and stay under 16 KB; rooms expire after 30 min.

Testing

  • Unit (Vitest, node): rooms server, rooms client, session over an in-memory link pair, frame recorder against a real Map2D, sprite mirror, view mirror, keyboard source, welcome 3-way menu, team name entry, leaderboard name format.
  • End to end (agent-browser, headed): two browser sessions on the dev server. The host creates a room, the guest opens the link, both play a stage, and team initials land on the leaderboard.
Known limits: no TURN relay; no reconnecting after a drop; guest input reaches the host after one network round trip (the guest's tank responds ~RTT/2 + one frame later than the host's).
